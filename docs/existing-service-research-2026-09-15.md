# 기존 서비스 분석·PO 인터뷰·계산 보완

2026-09-15 · 분석 기준 `main e582017` · 새 연구 계약 `npd.research.v2`

기존 Stage 1의 17개 작업, 연구 범위 선택, 12영역 PRD, 근거 그래프와 인계 기능은 유지합니다. 이번 변경은 기존 서비스 분석을 PRD에 활용할 때 필요한 상세 구조와 PO 확인 절차, 재현 가능한 집계를 보완합니다. 첨부 예시의 제품 운영 기능은 분석할 대상이며, NPD Assistant에 광고 집행 기능을 추가하라는 요구로 해석하지 않았습니다.

공통 양식이 자료의 진실성이나 모든 자연어 의미를 자동 판정하지는 않습니다. 입력의 범위·대표성·비교 가능성·원인 판단은 근거와 PO 검토가 필요합니다. 자료 성격 `OBSERVED`도 실제 조사나 UAT 완료 인증은 아닙니다.

## 사용 순서

1. **기존 서비스 PRD·매뉴얼**에서 자료 성격을 지정해 업로드하고, 분석 질문을 입력해 서비스 분석을 생성·검토합니다.
2. **연구 작업·PRD 준비**에서 조사 브리프를 선택합니다. 검토 서비스 문서를 선택하고 **검토 서비스 문서를 상세 표로 분석**을 실행하거나 **현재 업무·문제** 산출물을 직접 작성합니다. AI 기능은 설정된 제공자를 사용하고 항상 검토할 초안으로 저장합니다.
3. 상세 표와 미결 질문을 검토합니다. 문서에 없는 항목은 미확인 내용과 확인 계획을 명시합니다. 원문에 없는 동작·수치·답변을 채우지 않습니다.
4. **미결 질문으로 PO 인터뷰 준비**를 실행합니다. 인터뷰 전에는 모든 질문이 미결이며 `NOT_RUN`입니다. 실제 답변 또는 명시적인 합성 시연 답변을 구분해 기록합니다.
5. 답변의 관계를 문서 내용 확인/운영 변경/문서 오류/예외/희망사항으로 분류합니다. 검토한 답변과 반영 문장을 선택해 **별도 개정안 작성**을 실행합니다. 관련 표와 기준일을 보완해 다시 검토합니다.
6. **지표 합산 계산**, **누적 퍼널**, **VoC 코딩 집계**에서 집계 조건과 근거를 작성합니다. 표의 행 추가·삭제, 숫자 입력, 결과 표시와 버전 이력을 사용할 수 있습니다.
7. 사용할 최신 산출물의 버전을 연구 묶음에 선택하고 연구/개발 준비를 각각 검사합니다. PRD 초안 및 JSON/Markdown 인계에는 검토 내용과 자료 성격·계산 결과가 포함됩니다.

합성 자료를 기반으로 실제 검증을 주장할 수 없습니다. 실제 고객 확인은 별도의 실제 조사 자료와 검토 경로로 수행합니다. 운영 변경과 예외에 대한 PO 확인은 고객 수요 검증과도 다릅니다.

합산 계산은 비음수 분자·분모의 단일 비율을 지원합니다. 임의의 다단계 수식 실행기나 전체 SQL 로그 분석기는 아닙니다.

## 데이터·권한·호환성

- 별도 DB 이관 없이 새 레코드는 v2로 저장합니다. 이전 텍스트 분석도 읽고 편집할 수 있으나, SV-02를 필수로 지정한 연구 준비 검사는 상세 표 보완을 요구합니다.
- 표마다 최대 100행, 비어 있지 않은 고유 행 ID와 열 계약을 검사합니다. 계산 결과는 서버에서 재계산하며 클라이언트의 결과·성격 덮어쓰기를 신뢰하지 않습니다.
- 기존 원본의 누락된 자료 성격은 미확인입니다. 명시적인 전체 합성 선언을 새 업로드에서 인식하는 것은 보조 검사이며 모든 자연어 합성 표현을 탐지하는 분류기는 아닙니다. 이미지·기존 미분류 자료는 사용자가 성격을 확인해야 합니다.
- 원본이 바뀌면 연결된 검토·인터뷰·개정안·묶음·인계도 재검토 대상입니다. 사용자가 과거 문장을 새 자료의 사실로 자동 승격할 수 없습니다.
- 담당자·날짜·근거 유무는 PO 확인 기록입니다. 외부 인증기관의 진실 인증이나 서명 검증은 아닙니다.
- 예시 원본·사업 데이터·실제 고객 자료는 저장소에 추가하지 않았습니다. 테스트는 독립적인 합성 자료만 사용합니다.

## 검증 기록

- 새 21개와 기존 61개가 관련 Python 검사이며, 전체 실행에도 포함됩니다.
- 전체 Python의 Windows UTF-8 실행은 263개 중 250개 통과, 기존 플랫폼 비호환 13개 실패였습니다. 디렉터리 교체·symlink·POSIX 권한 조건이며 테스트를 제외하지 않았습니다. 기본 Windows 문자 인코딩 실행의 추가 자료 읽기 오류는 UTF-8 모드에서 해소됐습니다.
- DOM/HTTP 5개, 실제 로컬 Edge 16개가 통과했습니다. 새 검사는 자료 성격 선택, 혼합 파일별 성공·실패, 인터뷰 답변 검토·선택 반영, 계산 행 편집·검토, 버전 이력과 모바일 폭을 포함합니다.
- 지원 플랫폼의 전체 결과는 이 브랜치 커밋의 GitHub CI에서 Python 263개·DOM 5개·Chromium 16개를 각각 3회 실행해 확인합니다. CI 성공 여부는 PR의 해당 커밋 검사 결과가 기준입니다. Windows 반복 UI 검사에서 갱신·레이아웃 대기를 보강했으며, 관련 두 시나리오도 재통과했습니다.
- 실제 Bedrock 응답의 의미 정확성, 한국어 OCR, 사내 데이터/AXIOM/AWS 운영 연결, 실제 PO/고객 인터뷰, UAT와 작성 시간 절감 측정은 미실행입니다. 기존 코드·계약과 합성 테스트의 완료를 실제 운영 완료로 표시하지 않습니다.
