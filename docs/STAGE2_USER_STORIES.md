# 2단계: PO 사용자 스토리 정의

2단계는 쿠팡애즈 PO의 기획 의도를 구조화하고 검토하는 작업 공간이다. 손글씨 해석과 AI 제안은 초안이며, **PO 정의 확정과 실제 고객 검증은 서로 다른 상태**로 유지한다.

## 메뉴와 사용 순서

| 메뉴 | 작성·검토 내용 |
| --- | --- |
| 2.1 상품 정의 | 고객, 문제, 가치, 기대 경험, 기존 기능과의 차이, 공개 근거, 참고 PRD |
| 2.2 사용자 스토리 | 초안 가져오기 / 스토리 맵 / 원본 대조·편집 / 검토·확정 |
| 2.3 기능 요구사항 | 확정 스토리 버전에 연결한 조건, 시스템 동작, MoSCoW 우선순위 |
| 2.4 제약·비기능 | 권한, 정책, 데이터와 비기능 조건을 기록하는 편집 필드 |
| 2.5 범위·성공 지표 | 포함·제외 범위, 가설, 측정 방법과 판단 기준 |
| 2.6 PRD 검토·전달 | 확정안 미리보기, JSON/Markdown 내보내기, 새 PRD 초안 만들기 |

1. 2.1에서 상품의 기준을 저장한다. 참고 PRD를 선택하면 AI 해석 입력에 그 PRD의 내용을 포함하고 버전을 추적한다.
2. 2.2의 **초안 가져오기**에서 PNG/JPEG 또는 텍스트 메모를 저장한다. 모델 없이도 **스토리 직접 작성**은 가능하다.
3. **AI로 스토리 초안 해석**을 실행한다. 후보를 검토하고 **새 스토리로 채택**한다. 해석 실행 자체는 기존 스토리를 변경하지 않는다.
4. **원본 대조·편집**에서 판독 영역과 필드별 출처를 확인한다. 필드는 `원본에서 추출 / AI 제안 / PO 작성·수정`으로 구분한다. 이 라벨은 정확도 점수가 아니다.
5. 대상 사용자·문제·목표·가치·시나리오, 예외, Given/When/Then 수용 기준, 미해결 질문, 근거 또는 가정과 검증 계획을 작성한다.
6. 먼저 초안을 저장하고, 원본 의미와 수용 기준 검토 항목을 체크한 뒤 **이 버전의 정의 확정**을 누른다. 저장하지 않은 수정 사항은 확정할 수 없다.
7. 확정 스토리를 2.3 기능 요구사항에 연결한다. 2.6에서 전달 내용을 미리 보고 내보내거나 새 PRD 초안으로 만든다. 기존 PRD는 보존된다.

스토리 맵은 사용자 활동을 열로, MVP·후속·제외를 행으로 표시한다. 카드의 에픽·활동·출시 범위는 편집 화면에서 수정한다. 드래그 정렬은 이번 구현에 포함하지 않는다. 한 카드를 여러 제목으로 분할하거나 여러 카드를 한 제목으로 병합할 수 있다. 새 초안은 원본 참조·질문·상위 버전 이력을 유지하며, PO가 각 스토리의 내용과 수용 기준을 다시 작성한다.

## 원본·버전·권한

- PO 기획 이미지는 `planning_asset`으로 저장한다. 소유자 전용 `source` 리서치 경로를 개방하지 않는다. 모든 접근은 로그인 세션의 프로젝트 멤버십으로 제한한다.
- 이미지 원본과 처리용 사본, 텍스트 원본은 암호화한다. 이미지는 EXIF 방향을 보정하고 메타데이터를 제거한 JPEG 사본을 화면과 모델에 전달한다. 투명 영역은 흰색으로 합성한다.
- 정지 PNG/JPEG 장당 3MiB, 가로·세로 8,000px, 2,000만 화소 이하를 지원한다. SVG, GIF, 동영상, 다중 페이지 스캔 PDF, 원근 보정, 여러 장의 일괄 해석은 포함하지 않는다.
- 같은 원본은 프로젝트별 SHA-256으로 중복 처리한다. 철회된 자료의 재업로드는 자동 활성화하지 않는다.
- 서버는 모델 응답 스키마·영역 ID·좌표·필드 출처를 검사한다. 판독이 불확실한 영역에는 필수 확인 질문을 추가한다. 필수 질문은 삭제할 수 없고 답변 또는 범위 제외 사유를 남겨야 한다.
- 재분석 결과는 별도 해석 기록이다. 기존 스토리에 반영하려면 변경 전후를 비교하고 필드를 선택한다. 선택하지 않은 PO 수정과 수용 기준은 보존한다. 변경 후 확정 상태는 해제된다.
- 모든 수정·확정에는 `expected_version`이 필요하다. 생성 중 입력 변경, 동시 확정, 오래된 화면의 수정은 409로 거절한다.
- 원본 철회, 공유 근거 변경, 참고 PRD 버전 변경은 연결된 스토리·요구사항·PRD의 조회와 내보내기에 적용한다. 상품 기준만 바뀐 스토리는 명시적으로 현재 기준의 검토용 초안을 열 수 있다. 철회된 근거를 지워 파생 내용을 다시 공개하는 것은 차단한다.
- 이미 내려받은 파일은 회수하지 못한다. 원본을 모델에 보내는 것은 **AI로 스토리 초안 해석**을 실행할 때이다. 기획 이미지는 실제 고객 검증 자료로 자동 분류하지 않는다.

## 모델 설정과 실제 검증

이미지 해석은 기존 AWS Bedrock `BEDROCK_MODEL_ID`와 리전을 사용하며, 선택한 모델·추론 프로필이 Converse 이미지 입력과 설정한 출력 형식을 지원해야 한다. 실제 바이트를 Converse image content block으로 전달한다. 모델 미설정·미지원·잘못된 응답은 실패로 표시하며 고정 응답으로 대체하지 않는다. 텍스트 작업은 설정된 제공자를 사용한다. OpenAI 이미지 어댑터는 이번 변경에 포함하지 않는다.

자동 테스트는 합성 이미지와 명시적인 모델 대역으로 권한·저장·버전·UI 연동을 검증한다. **한국어 손글씨 판독 정확도와 실제 Bedrock 응답 품질을 입증하지 않는다.** 고객 시연 전 실제 설정으로 선명한 메모, 흐린 필기, 부정 표현, 화살표·그룹, 여러 스토리가 섞인 사진을 PO가 검토하고, 판독 오류·의미 왜곡·수정량·지연·비용을 기록해야 한다.

## 전달 형식과 제한

`npd.story-package.v1`에는 상품 기준, 현재 유효한 확정 스토리 버전, 수용 기준, 원본·해석 ID, 필드 출처, PO 확정 이력, 고객 검증 계획, 기능 요구사항과 공개 근거 메타데이터가 포함된다. 원본 이미지·암호문·비공개 리서치는 포함하지 않는다. Markdown에도 근거 ID·버전·유형·적용 조건·한계를 보존한다.

이는 NPD 자체 교환 형식이다. **AXIOM 실제 수신·스키마 매핑은 미검증**이며 AXIOM 버튼이 외부 시스템에 게시하지 않는다. 새 PRD 생성은 기존 PRD 크기 제한(전체 100,000자)을 따른다. 고객 검증 결과 등록·승인 워크플로, 이슈 트래커 연동, 변경된 참고 PRD 간 자동 의미 비교는 후속 범위다.

## 개발자 검증

```bash
python -m pip install -r requirements.txt
npm ci --ignore-scripts
npx playwright install --with-deps chromium
python -m unittest tests.test_stories -v
node --test tests/stories_browser.cjs
python scripts/regression.py --passes 3 --browser
```

기존 DB는 서버 시작 시 필요한 유일 인덱스만 추가한다. 스토리와 기획 자산은 기존 버전 레코드 저장소를 사용한다. 실행 데이터와 암호화 키는 계속 비공개 데이터 디렉터리에 둔다.
