# Stage 1 연구 산출물과 PRD 준비 계약

2026-09-15 · 적용 기준: S1-ADD-001–019 · 데이터 계약: `npd.research.v1`

연구 결과를 자유 서술로 모아 전달하던 경로에 **조사 범위 → 작업별 검토 산출물 → 명시적으로 선택한 버전 묶음 → 12영역 PRD** 경로를 추가했습니다. 문서 확정과 실제 고객 검증, 개발 승인, UAT 실행, 외부 시스템 수신은 독립 상태입니다.

이 문서는 공개 가능한 구현 설명입니다. 요구사항 첨부 원문, 예시 PRD의 사업 정보, 실제 고객 자료와 실행 인증 정보는 포함하지 않습니다.

## 사용 순서

1. **연구 작업·PRD 준비**에서 조사 브리프를 만들고 제품·시장·사용자 범위, 결정 질문, 제외 이유, 책임자와 시점, 수행할 작업을 지정합니다.
2. 아래 작업별 산출물을 작성합니다. AI 초안은 사용자가 선택한 검토 근거와 설정된 실제 제공자를 사용합니다. 필요한 필드는 빈 초안으로 저장할 수 있으며, 검토 완료는 필수 내용과 참조 버전을 다시 검사합니다.
3. 근거·문제·스토리 후보·요구사항·인수 기준·UAT·지표를 만들고 연결의 의미와 이유를 기록합니다. 화면에서 편집한 내용은 **내용 저장 후 검토 완료**가 저장한 바로 그 버전을 검토합니다. 실패하면 최신 초안을 다시 표시합니다.
4. 검토한 브리프와 산출물의 정확한 버전으로 묶음을 만들고 **PRD 작성에 이 버전 사용**을 선택합니다. 같은 프로젝트라도 다른 연구의 산출물을 섞을 수 없습니다.
5. 연구 준비 검사를 실행합니다. **12영역 PRD 초안**은 선택한 검토 내용을 관련 영역에 배치하는 편집 가능한 초안입니다. 아직 비어 있는 영역을 작성하거나 허용되는 영역에 N/A와 이유를 기록합니다. AI 생성도 별도 동작으로 사용할 수 있습니다.
6. PRD 준비 조건을 확인한 뒤 PO 확정을 수행합니다. 개발 검토 준비는 별도 검사입니다. JSON/Markdown 인계와 수신 대조를 각각 수행합니다.

새 문서의 간단한 개요 한 문단은 PRD 준비 검사에 통과하지 않습니다. PO 확정은 검토 조건 충족을 기록하며 고객 검증 성공을 생성하지 않습니다.

## 검토 조건과 보안

- 근거 유형: PUBLIC_FACT, ATTACHMENT_STATEMENT, INTERNAL_MEASUREMENT, REAL_VOC, SYNTHETIC_FGI, ASSUMPTION, USER_REQUIREMENT. 실제 수요 검증에는 적합한 실제 근거가 필요합니다.
- UNKNOWN 기준선은 숫자 없이 이유와 다음 측정을 기록합니다. 제안 목표, 외부 실측, 합성 데이터가 우리 제품의 실측 기준선으로 자동 전용되지 않습니다.
- 실제 조사와 UAT의 기본 상태는 NOT_RUN입니다. AI 초안은 실제 실행을 확정할 수 없습니다.
- 연구 준비는 요구된 작업의 검토, 연결 그래프와 내용 조건을 확인합니다. 미해결 충돌·미확인 근거는 경고로 유지합니다. 개발 검토에서는 해당 단계의 중요 충돌·미결 질문·필요한 실제 조사 미실행이 차단 조건입니다.
- 원본 교체, 공유 철회, 산출물 변경은 후속 레코드의 정확한 의존 버전을 무효화합니다. 영향 화면은 ID/버전만 표시하고 보호된 본문을 다시 노출하지 않습니다.
- 기존 자료 소유자 전용 원본은 새 작업 화면이나 AI 생성이 복호화하지 않습니다. 소유자가 명시적으로 수행하는 기존 원본 추출 동작만 원본을 모델에 전달할 수 있습니다.
- 인계 패키지는 검토 산출물과 묶음 내부 연결을 내보냅니다. 내부 원본 참조·암호문·전사·파일명은 자동 첨부하지 않습니다. PO가 직접 작성한 공개 가능 문장의 내용은 PO의 검토 책임 범위입니다.
- 과거 인계 비교와 수신 대조도 현재 접근 철회 여부를 검사합니다. 이미 다운로드된 파일을 회수하지는 못합니다.

## API 및 버전

`GET /api/research-workspace`는 작업·필드 계약, 현재 산출물과 묶음, 선택한 버전, 실제 입력 상한을 제공합니다. `/impact`, `/exports`, `/receipts`는 영향과 인계 기록을 제공합니다.

`POST /api/research-workspace/` 아래 동작:

| 경로 | 동작 |
| --- | --- |
| items, items/review, items/withdraw | 초안 저장, 명시적 검토, 철회 |
| generate | 선택한 검토 근거를 사용하는 실제 모델 초안 |
| packs, select | 같은 연구의 정확한 버전 묶음, 생성 기준 선택 |
| gate | stage=research/development 준비 조건 검사 |
| compose | 12영역 PRD 편집 초안 작성 |
| export | npd.research-handoff.v1 JSON/Markdown, 해시·변경분 |
| receipt | export ID/해시/모든 산출물 버전/수신 ID 대조 |

수정·검토에는 `expected_version`이 필요합니다. 생성·저장 중 입력 또는 권한이 바뀌면 프로젝트 epoch 검사로 실패합니다. 클라이언트가 project_id·role·검토 상태를 보내도 권한을 얻지 못합니다.

`POST /api/definitions/readiness`는 12영역과 연결된 연구 묶음 준비 상태를 검사합니다. PRD 확정에 이 검사가 적용됩니다. 수신 대조는 `PO_RECONCILED`, `live_transport_verified=false`로 기록합니다.

## 기존 데이터와 처리 상한

별도 일괄 DB 마이그레이션은 없습니다. 새 레코드에 계약 버전을 저장하고 과거 자료는 기존 편집 경로로 읽습니다. 과거 확정 PRD를 새 기준 통과로 소급 인정하지 않으며, 이전 내보내기는 새 준비 검사 미평가로 표시합니다. 새로운 연구 산출물 또는 검토 결과가 있는 프로젝트는 연구 묶음을 선택한 뒤 AI 기획을 실행합니다.

기존 인사이트의 research/synthetic 구분을 보존합니다. 세부 분류·원문 위치가 없으면 검토 필요로 읽으며, 부분 편집으로 합성 유형이나 위치가 사라지지 않습니다. 이전 자산 팩의 문자열 위치는 legacy_label로 보존하고 NEEDS_REVIEW로 읽으며, 검증된 문자 위치로 승격하지 않습니다. 새로 입력한 원문 위치는 서버의 추출 위치 목록과 대조합니다.

현재 상한은 파일당 3MB, 스토리 생성에 선택하는 원본 분석 3개, 이미지 16,000,000픽셀 및 한 변 8,000픽셀입니다. 새 작업의 AI 입력은 100,000자 JSON, 기획 맥락/편집 초안은 별도의 크기 검사로 제한합니다. 브리프를 포함한 묶음은 100개 이내입니다. 필수 내용을 조용히 잘라 전달하지 않습니다. 입력 상한 변경 제안은 기록할 수 있지만 런타임 상한을 변경하지 않습니다.

상위 근거가 변경된 새 연구 경로는 현재 근거로 새 산출물을 작성·검토하고 새 묶음을 선택합니다. 오래된 본문을 자동 재기반하거나 비공개 내용을 복구하지 않습니다. 기존 스토리의 직접 원본 교체 비교·편집 복구는 기존 경로를 사용합니다.

## 검증

- Stage 1 합성 회귀 24개: 정본 일관성, 범위/권한, 17개 작업 계약, 수치 의미, 출처 계열, 실제/합성 분리, 충돌, 12영역, 그래프, 원본 변경, 보호된 인계, AI 입력, 수신 대조, 부분 편집, 기준선, 대안·효과 측정.
- 기존 Stage 2/원본 검사 37개와 새 검사 24개의 표적 실행은 61개입니다. 문자열 원문 위치의 이전 자산 팩 호환 회귀도 포함합니다. 241개 시점의 Windows 전체 실행은 228개가 통과했고 기존 플랫폼 비호환 13개만 실패했습니다. 이후 문자열 위치 호환 검사를 추가했습니다.
- 실제 로컬 Edge 브라우저 15개와 DOM/HTTP 5개 통과. PO 편집 직후 검토, 검토 실패 후 재시도, 명시적 묶음 선택, 누락 표시, 모바일 폭을 포함합니다. 데스크톱·모바일 캡처를 확인했습니다.
- 지원 전체 검증 플랫폼은 Linux/Python 3.12/Node 22입니다. GitHub CI는 전체 Python·DOM·Chromium을 각각 3회 수행하고 Docker 시작/HTTP, 인프라 lint와 문법 검사를 수행합니다. 성공 여부는 변경 커밋의 Actions 결과로 확인합니다.
- Windows 네이티브 전체 실행에는 기존 디렉터리 교체·symlink·POSIX 권한 관련 13개 비호환 실패가 있습니다. 새로운 기능의 오류와 구별하며 테스트를 숨기거나 제외하지 않습니다.

실제 Bedrock/Brave 응답의 정확성, 한국어 손글씨·스캔 OCR, 사내 데이터·AWS/S3·AXIOM 연동, 광고주 조사, 운영 성과와 고객 UAT는 이 합성 회귀로 검증되지 않습니다. 해당 실행에 필요한 규격·대상·접근 권한과 실제 측정 계획이 있어야 후속 수용 검증을 진행할 수 있습니다.
