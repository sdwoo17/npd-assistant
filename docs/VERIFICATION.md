새 검증은 PO 이미지·텍스트 입력, 이미지 바이트를 포함하는 Bedrock Converse 요청, 스키마·영역 참조 거절, 모델 실패 시 초안 미생성, 요청 중복·입력 변경, 서버 재시작, 원본/근거 철회, 재분석 중 입력 변경, 기존 PO 수정 보존, 선택한 수용 기준 반영, 미해결 질문·동시 확정, 상품 기준/참고 PRD 버전 변경, 분할·병합 이력, 요구사항·PRD 버전 의존성과 내보내기를 다룬다.

브라우저에서는 실제 PNG 업로드 → 합성 모델 해석 → 원본 영역 대조 → PO 수정·확정 → 스토리 맵 → 기능 요구사항 → JSON 다운로드·새 PRD 생성 → 재분석 시 수정 보존 → 프로젝트 전환 후 이미지 비노출을 검사한다. 기존 소유자/PO 흐름과 CSRF·격리 검증은 유지한다.

**실제 Bedrock 이미지 응답, 한국어 손글씨 정확도, 고객 UAT와 AXIOM 수신은 이번 자동 검사에 포함하지 않는다.** 테스트 이미지와 모델 응답은 명시적인 합성 대역이며 실행 앱에서 import하지 않는다.

[이번 반복 실행 기록](bedrock-regression-summary.json)은 9번의 테스트 묶음 실행 결과다. 110/2/6은 서로 다른 테스트 수이고 반복을 새 시나리오 수로 계산하지 않는다. 기존 20개 시드의 CSV 1,000행/상태 전환 300단계도 매 Python 실행에 포함된다. 회귀 테스트 안의 모델과 실제 HTTP live gate의 자체 테스트는 명시적인 test double이다. SDK Stubber도 네트워크 호출은 하지 않는다.

GitHub CI에는 동일 회귀 루프·CloudFormation lint·Docker 빌드 및 HTTP 시작·컨테이너 내 live gate import 검사를 포함했다. 최종 CI 결과는 해당 변경 커밋의 Actions 실행에서 확인한다. 템플릿은 정적 검증을 통과했지만 실제 AWS에서 설치·IAM·네트워크를 검증한 것은 아니다.

이번 수정 중 SDK 시간 초과 예외의 `response=None` 처리, 컨테이너에서 scripts가 제외되던 구성, Amazon Linux 기본 Python 버전, 비관리자 계정의 설치 코드 읽기 권한을 바로잡았다. 기존 EC2 user-data 변경을 앱 업데이트로 간주하지 않도록 배포 도구는 신규 스택만 허용한다. [실행과 고객 테스트 순서](BEDROCK_PILOT.md)를 따른다.

## 비공개 자산 임포터 추가 검증

`test_demo_assets.py` 8개를 추가해 총 93개 Python 테스트를 각각 3회 통과했다. 비공개 초안 상태, 8명 태그와 후속 반박, 디브리프, PRD v2, 기존 데이터 보존, 잘못된 참조·중복·실제 VoC 혼입·외부 경로·심볼릭 링크·JSON 오류의 반복 실패 및 임시 DB 정리를 확인했다. 새 가져오기 코드는 모델을 호출하지 않는다.

별도로 작성한 비공개 데모 팩은 합성 VoC 240건(80개 사건의 3개 채널), 인사이트 16개, 페르소나 8개를 실제 적재했다. 20개 질문을 각 5회 검색하고 연구 근거를 지정한 질문 13개에서 기대 근거 중 하나 이상을 찾았다. 이는 검색 결과의 근거 존재 확인이며 전체 검색 정확도·응답 품질 검증은 아니다. 실제 Chromium에서 PO의 페르소나 카드 8개와 비공개 원문 메뉴 차단, 페이지 오류 없음을 확인했다. 원문과 상세 자산·결과는 공개 저장소에 포함하지 않는다.

합성 데이터에 작성자 라벨을 적용한 시드와 AI 분류 성능을 구분한다. 무라벨 규칙 분류의 주분류 일치는 66/240(27.5%)이었다. 작성자 택소노미/라벨과의 진단 값으로 실세계 정확도나 LLM 성능이 아니다. 실제 AI 품질·FGI의 대표성과 현실성은 모델 연결 후 별도로 검증해야 한다.

## 180건 사용자 제공 CSV 실측

첨부 CSV 원문은 저장소에 게시하지 않았으며 임시 DB에서 실행 후 제거했다. [집계 결과](benchmark-voc-180.json)에는 본문과 외부 ID가 없다.

- 최초 적재 **180건 / 중복 0 / 오류 0**, 약 **96ms**.
- 같은 출처 재적재 **추가 0 / 중복 180**.
- 전부 `synthetic`. 정답 기능 라벨이 있는 행은 **0건**.
- 기본 규칙의 주 기능: creative_test 60, reporting 25, budget 16, workflow 6, **미분류 73건(40.56%)**.
- 4개 질문을 각 20회 검색: 24건 반환, 중앙 지연 약 **27~28ms**, p95 약 **33~40ms**. 로컬 환경 수치이며 동시 사용자 부하나 관련성 정확도 검증이 아니다.

**규칙 분류의 정확도가 개선됐다고 주장하지 않는다.** 사용자가 보고한 재현율 0.53을 이 무라벨 파일로 재현할 수 없다. 프로젝트 기능 트리·AI 분류·PO 보정 경로를 구현했지만 실제 분류 품질 게이트는 PO가 판단한 정답 라벨과 실제 모델이 필요하다. 어휘 검색도 임베딩 검색으로 바뀐 것이 아니다.

| AT-14 철회 | 모든 입력·간접 대화·집계 근거의 버전 의존성, 재조회·export 마스킹 | 이미 외부로 내보낸 파일의 수신 측 처리 |
| AT-15 모델 실패 | 명시적 실패, 턴 롤백, 재시도/idempotency, 고정 응답 폴백 없음 | 실제 리전/IAM/모델 접근, rate limit·지연 |
| AT-16 전체 재현 | 실제 브라우저+HTTP+DB, 모델 부분만 test double | `live_validation.py --run` 및 실제 PO UAT |

## 수정 중 발견해 막은 회귀

- 기능 키워드의 단일 버킷 흡수를 복수 연결로 변경하고 AI·PO 분류 경로 추가.
- 원천 외부 ID 소실 및 출처:ID 문자열 경계 충돌 제거.
- PO 초기 발언/결정의 누락, 단순 상태만 바뀌던 PRD 채택을 실제 문단 변경으로 수정.
- 최종 인용에서 제외된 입력, 과거 대화, 집계 분모를 통해 남던 간접 지식 의존성 차단.
- 생성 중 철회·동시 수정·두 번째 페르소나 실패·DB 실패·중복 요청에서 부분 결과 저장 차단.
- 잘못된 빈 배열 날짜/필터 수용, 날짜 필터 때문에 리뷰 페이지 수집이 일찍 멈추는 결함 수정.
- 실제 Apple RSS 호출에서 `sortBy=mostRecent` 대소문자 계약을 확인해 빈 결과가 나오던 주소 오류 수정.
- 근거의 수치를 다른 단위로 바꾸는 응답 거절. 이는 문장 전체 의미의 자동 진실 판정이 아님.
- 버전 없는 이전 MVP 생성 산출물은 불완전한 provenance를 신뢰하지 않고 재확인 처리.

## 릴리스 판단

소스 변경과 명시한 자동 회귀는 완료 범위다. 고객 데모를 실제 AI로 완료했다고 판정하려면 모델 접근 권한이 있는 환경에서 live gate를 실행하고, 라벨 있는 실제/합성 평가 자료로 분류·검색·인터뷰 품질을 PO가 검토해야 한다. AXIOM과 기존 CloudFront 서비스는 [통합 지침](INTEGRATION.md)에 따라 별도 연계한다. 이 기록을 “100% 모든 경우를 검증했다”는 주장으로 사용하지 않는다.

8개 페르소나를 실제 표시하면서 발견한 입력창 밀림도 수정했다. 데스크톱 채팅과 근거 패널의 높이·스크롤을 분리하고 브라우저 테스트에서 입력 버튼이 1,000px 뷰포트 안에 남고 하단 진행 제어에 접근 가능한지 검증한다.
