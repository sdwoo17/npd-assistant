# 기존 AWS NPD 및 AXIOM 연계 경계

## 현재 자산 관계

이 저장소는 신규 독립 코드베이스 C이다. CloudFront 배포본 A의 소스·실행 환경과 연결됐다는 검증은 없다. Creative Studio B의 광고 분석 프로토타입 기능도 자동 포함되지 않는다. 기존 앱에서 어떤 격차가 이미 해결됐는지는 실제 소스와 배포 설정 확인 후 판단한다.

## AWS 앱에 이식할 계약

| 현재 모듈 | 이식할 동작 | 대상 환경에서 확인할 것 |
| --- | --- | --- |
| store | 프로젝트 멤버십, 세션, 버전 CAS, 일괄 원자 저장, 지식 epoch | Cognito 그룹/멤버십, DynamoDB 또는 RDS 트랜잭션, KMS와 백업 |
| research | 원문 격리, 청크 추출, 비공개 초안, 명시적 공개, 작업 재시도 | S3 원문 버킷 정책, 큐·작업자, 업로드 한도 |
| voc | 원천 ID, 복수 기능 연결, 기간 분모, PO 보정 | 기존 스크레이퍼 어댑터와 프로젝트 범위, 개인정보 정제 |
| chat/planning | 의존성 버전 전파, 인터뷰 원자 저장, PO 결정, PRD 실제 반영 | 스트리밍 중 오류/철회 처리, 조건부 쓰기, 사용자별 동시 요청 |
| model | Bedrock JSON Schema/도구 형식 및 출력 검증 | 대상 리전·모델 지원, IAM, 실호출 지연·한도·비용 |

기존 플랫폼으로 이식할 때 이 저장소의 HTTP 인증 테스트, 카나리/철회/프로젝트 격리/동시성 테스트의 수용 조건을 유지한다. `Service`는 웹 프레임워크와 분리했지만 Store 호출 인터페이스까지 자동 AWS 호환인 것은 아니다. 어댑터와 원자성 계약을 명시적으로 구현해야 한다.

## AXIOM 전달

`GET /api/export/{conversation_id}?format=markdown` 또는 JSON의 `npd.research-package.v2`를 전달한다. 패키지는 승인된 인사이트/가명화 VoC, 근거 ID/버전, PO 결정, 가상 인터뷰 구분, 디브리프, PRD 변경 전후 및 실제 반영 버전을 포함한다.

이것은 자체 교환 형식이다. AXIOM API·ontology 스키마·인증·공식 수신 규격은 제공되지 않아 직접 동기화를 구현했다고 주장하지 않는다. 쿠팡애즈 측에서 다음 세 가지를 실제로 확인해야 한다.

1. Markdown 붙여넣기/파일 첨부 후 인용 ID와 실제 출처 연결을 보존하는가?
2. 동일 PRD 문단 및 버전 매핑과 재전송 중복 처리를 어떻게 정의하는가?
3. 이 도구에서 근거를 철회한 경우 이미 AXIOM으로 전달된 자료의 보류·삭제·재검토를 어떤 API와 정책으로 전달하는가?

운영 통합에서는 Cognito/RDS/KMS/비동기 큐/관찰 가능성/백업 복구를 실제 환경에서 검증한다. Docker 컨테이너의 로컬 실행 성공을 공개 SaaS 운영 완료로 해석하지 않는다.

## 붙여넣은 PRD의 인용 확인

PRD 화면 또는 `POST /api/citations/verify`에 수신 PRD 본문을 넣으면 현재 프로젝트의 공개 근거 ID 및 버전과 대조한다. 반복 횟수와 서로 다른 유효 근거 수를 구분하며 미확인·철회·버전 불일치를 표시한다. 본문은 서버에 저장하거나 모델에 전달하지 않는다. 이 기능은 붙여넣은 결과의 점검이며 AXIOM API 접속, 자동 수신, 외부 권한 검사 또는 인용 의미의 정확성을 검증하지 않는다.

FGI 패키지에는 연구 설계·질문·모집 기준·모집 당시 페르소나 버전·가이드·완료 검토본 연결이 포함된다. 최종 수신 검증에는 실제 AXIOM 스키마/예제, 인증 방식, 수신 테스트 환경과 철회 전달 정책이 필요하다.
